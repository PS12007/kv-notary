KV-cache integrity · Llama-3.2-1B · Qwen2.5-0.5B

A KV cache is a claim about a prompt.
kv-notary checks it.

Serving stacks now ship KV caches between machines: prefill workers to decode workers, shared prefix caches, sessions saved to disk. Nothing checks that a cache actually encodes the text it came with. One forged column out of ~450 changes the model's answer while the prompt stays exactly the same. Recomputing a handful of the right columns catches it.

Audit a cache

A memo is cached, and later a trusted node asks a question about it. Pick a cache and see what the model answers from it. Then audit it: recompute some of its columns from the tokens and compare. Shading shows how much the question and answer read each token. Everything here was computed with the real models; the page only replays it.

How the check works

01 · A CACHE IS A FUNCTION OF ITS TOKENS

Column p of an honest cache is what the model computes for token p while reading columns 0…p−1. If every column agrees with that recomputation, then by induction the whole cache is the honest one.

02 · RECOMPUTE A FEW COLUMNS

Recomputing column p against the claimed cache costs one token through the model. Checking 16 of 450 columns costs a few percent of a prefill. In bf16 the comparison needs a calibrated per-layer tolerance.

03 · CHECK WHERE THE QUESTION READS

A forged column only matters if the question reads it, and reading is attention, which the trusted node computes anyway. So audit the most-read columns first, and add random ones for attackers that spread their edit thin.

Results

Use it

from kvnotary import Model, Notary
m = Model("llama-1b")
notary = Notary(m)
notary.calibrate(honest_docs)                       # per-layer bf16 tolerance
verdict = notary.audit(doc_ids, received_cache, question_ids, answer_ids)
print(verdict)  # REJECT (columns [212] disagree with their tokens); checked 28 columns in 41 ms
